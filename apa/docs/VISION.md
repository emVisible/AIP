# APA 产品愿景与路线图 v1.0

## —— 出于栏而胜于栏：从「人学机器」到「机器懂人」

> 影刀给了 RPA 一门编程语言；APA 给 RPA 一句自然语言。
> 但我们不做减法的革命：键盘换了形态，输入的能力永远保留。

---

## 一、范式诊断：影刀架构的三个根本缺陷

### 1. 指令中心主义
600+ 指令按目录树排列，用户必须知道指令存在、找到它、学会参数。
影刀学院卖培训课是这个范式的直接后果——工具把学习成本转嫁给用户。

### 2. 流程 = 录出来的脚本
产物是一份可视化 BASIC 脚本。改需求=改脚本，交接=读脚本。
用户要的是结果，影刀卖的是造流程的 IDE。

### 3. AI 是外挂
LLM 被塞进菜单当第 601 个指令类别，没有改变核心循环。

## 二、核心命题：双环架构

```
┌─ 意图合成环（新增一等子系统）
│   自然语言 → IntentCompiler → process.yaml 草稿
│   · 能力目录 = Action Registry（131+ 动作本就是机器可读契约）
│   · 歧义 → 反问澄清协议
│   · 硬约束：产出动作必须 ∈ Registry（幻觉直接拒绝）
│   · 【人工确认门】草稿可见、可改、可评审
│
└─ 确定性执行环（现有引擎，原封不动）
    ProcessEngine 六步校验链 → 执行器 → Journal
    编译期用 LLM，运行期零 LLM —— 企业信任的地基
```

**与 AI Agent 自由奔跑产品的本质区别**：
我们产出确定性流程工件——审计、复跑、交接全部保留。
影刀的 AI Power 是旁挂聊天；APA 的意图环直接产出确定性流程。

## 三、虚拟键盘原则（交互三通道）

单一真相源 `process.yaml`，三条平等通道：

| 通道 | 定位 | 保留物 |
|---|---|---|
| 对话（新·主轴） | 表达意图 | 澄清式反问 |
| 画布（审查微调） | 可视化确认与精修 | 拖拽/弹窗编辑/循环体 |
| YAML/模板 | 专家通道/复用 | 导入导出/git 友好 |

指令目录树 → 坍缩为一个搜索框 + 对话中的上下文浮现卡片。
找指令的能力永不消失，只是不再需要翻树。
（iPhone 类比完整版：删除的是物理键盘的形态，保留输入的能力。）

## 四、分阶段路线图

### Phase A · 指令集完备（编译目标语言）【当前阶段】
- `if.*` 谓词查询族：element_visible / url_contains / text_on_screen /
  file_exists / dir_exists / window_exists → 统一返回 `{matched}`，
  condition 以 `steps.<id>.matched` 组合（不引入第二套条件语义）
- LoopContext 栈：`loop.break` / `loop.continue`（嵌套栈；无栈显式失败）
- foreach 字典支持：source 为对象时迭代 `{key, value}`
- while 支持 body_steps 子步骤（与 foreach 同构，控制流可用）
- 预算穿透：循环体子引擎 actions_sent 并入全局 max_actions 守卫
- wait.file(glob) / wait.window(title_contains)
- input.humanize 模拟真人开关（贝塞尔轨迹 + 高斯延迟）
- Registry 注解 pass：高频动作补 when_to_use（IntentCompiler 词表质量地基）

### Phase B · 意图环 MVP + 工作台
后端 `/api/intent/compile`：
- 策略一（首发）：模板检索+槽位填充——场景模板为骨架，LLM 填参+澄清
- 策略二（迭代）：自由编译——全 registry 组装，合法性硬校验兜底
前端工作台改造：
- 左=对话流（澄清/草稿播报/差异解释）· 右=画布审查视图
- 双向绑定：对话改→流程变；手改→APA 解释差异
验收锚点：电商 S1 价格监控「一句话→确认→试运行通过」≤3 分钟；
幻觉动作名注入拒绝率 100%。

### Phase C · 闭环与生态
运行失败回流修正建议 · few-shot 场景库扩充 · Capability Pack 架构
（词汇表稳定后做词汇组织）· 电商 App Package 试点（平台届时定）·
验证码外部服务适配（可选启用）
